# Real Groq run: openai/gpt-oss-20b, free plan, synthetic text calls, from cloud box (24 Nov 2026)

Machine-readable copy: [`groq-real-2026-11-24.json`](groq-real-2026-11-24.json). No key or header is stored in this report, the JSON, the traces or git.

## What was run and where

- **Provider/model:** Groq `openai/gpt-oss-20b`, **free plan** (no card, no paid tier). Streaming, `reasoning_effort: low`, hidden reasoning off (`include_reasoning: false`), `max_tokens` floor 400.
- **Where:** a cloud Linux box over the public internet. This is not a phone line and not the developer laptop.
- **Input:** synthetic **text** calls. There was **no audio**: STT, TTS and real-audio time to first audio were **not measured**.
- **When:** 24 Nov 2026, 12:30-12:47 PM PKT (07:30-07:47 UTC).
- **Throttle:** at least 3.1 s between model requests (≤ 20 requests/min); 429 retry-after backoff and a per-run request cap were active.
- **Total use:** 151 remote requests and about 52K tokens (free-plan limits: 30 RPM, 8K TPM, 200K TPD). There were 0 HTTP 429s and 0 errors.
- **Bill:** **$0**, because this is the free plan. The costs below use the dated price table (`config/llm-prices.json`, as_of 2026-11-24: $0.075 in / $0.30 out per 1M tokens). They show what the same tokens would cost on the paid tier.

Runs, in order: 2 smoke calls → replay with no cache (before fixes) → eval gate → probe run 1 → fixes → probe run 2 → fixes → **final runs**: probe, replay with no cache, replay with cache, eval gate.

### How "wrong answer" was measured
A wrong answer is one the caller would **hear** that contradicts the business config (`src/businesses/mm-dental.ts`). Two checks were used:

1. **Automatic:** guard blocks, fixture expectations, and the probe's `must_not` and abstain rules.
2. **Manual:** I read every one of the 55 final answers myself.

The replay's model turns cover only a few distinct FAQ questions, since most replay turns are rules or tools. The 30-question probe (`evals/llm-probe.jsonl`) was added to test hours, addresses, phones, prices and unanswerable questions. It sends each question straight into retrieval → response agent → guard. Its checks come from the config, not from model output.

## Honest limits

- The model still sometimes misreads the hours row (Tuesday at Uppingham). The guard catches that pattern now, but it only catches day/time/price/phone errors, not every possible misstatement.
- The fallback ladder waits for the **full** completion (the reply text is not streamed into TTS). The primary deadline is 650 ms. The p95 model-turn time was 403 ms, but one probe request had a 1.5 s TTFT; in the live runtime that turn would have dropped to the fallback. The "small" tier is the same gpt-oss-20b model.
- The samples are small (25 replay model turns, 30 probe questions, 1 business) and the text is synthetic. Network latency is from this cloud box to Groq; it is not phone or WebRTC transport.
- Not measured: STT, TTS, real-audio TTFA, and human-rated quality.
